# 构建与校验说明（维护用）

本目录是《C语言编程题库》的工具链。**内容全在上层 6 个 `.md` 里**，这里只负责生成网页和校验答案。

## 两个脚本

| 文件 | 作用 |
|------|------|
| `build.mjs` | 读 6 个章节 → 生成 `../C语言编程题库.html`（搜索/筛选/答案折叠/进度打勾/夜间/打印）；自带自检（编号唯一、题型与知识点齐全） |
| `verify.mjs` | 抽取所有 ````c-run```` / ````c-io```` 代码块，**真实 gcc 编译 + 运行 + 与紧随其后的 ````text```` 块逐字比对** |

## 日常命令

```powershell
cd 'D:\专升本\C语言编程题库'

# 校验所有参考答案（改了题目内容必跑）
& 'C:\Program Files\nodejs\node.exe' .build\verify.mjs

# 重新生成网页
& 'C:\Program Files\nodejs\node.exe' .build\build.mjs
```

````markdown

```text
````

### 代码围栏的三种用法

| 围栏 | 含义 | 校验方式 |
|------|------|------|
| ````c-run```` | **无输入**的完整程序 | 编译 → 直接运行 → 与后面的 ````text```` 逐字比对 |
| ````c-io```` | **有输入**的完整程序 | 编译 → 用 `// in:` 的数据喂 stdin → 比对 |
| ````c```` | 片段（如故意写错的反例） | 不校验 |

**多行测试输入**用这个写法（不能用 `\n` 字面量，会被 cmd 重定向截断）：

````c
```c-io
// in: <<<
5
3 9 2 7 5
// >>>
#include <stdio.h>
……
```
````

## 踩过的坑（别改回去）

1. **围栏切分必须「数嵌套」**。
   `answer` 块里嵌着 `c-io`/`text` 围栏，**它们和闭合符都在第 0 列**，靠缩进或「取最后一个裸围栏」都判错：
   - 取最后一个裸围栏 → 会一路找到文件末尾，把后面所有内容吞进第一个块（顶层只剩 1 个块）；
   - 正确做法：带 info string 的围栏嵌套 +1、无 info string 的 -1，**第一个归零的**才是闭合符。
2. **围栏的 info string 里可能有空格**（`answer 参考答案`），正则用 `\S*` 会匹配失败，必须 `(\S.*?)?`。
3. **`answer` 块里的子围栏要先「摊平」**再配对：`verify.mjs` 的 `flatten()` 会把 answer 的 body 递归 `scan()` 一遍，否则 `c-io` 和它的 `text` 隔着父块配不上对。
4. **本机沙箱禁止 Node 用管道捕获子进程输出**（`spawnSync EPERM`）→ 一律让 exe 自己重定向到文件再读回来。
5. **沙箱会把极少数 exe 判为「拒绝访问」**（换文件名、换目录都无效，与代码无关）→ 脚本把这类**单列为「沙箱拒绝执行」**，不计入失败，需人工用等价程序确认。
6. **编译产物按源码内容哈希命名、只增不删**：沙箱禁止删除 `.build/verify` 里 gcc 产出的 `.exe`，所以不能用「清空重建」的写法。
7. **`.ps1` 必须纯 ASCII**（本机 PS 5.1 按 GBK 读无 BOM 脚本，中文注释会破坏语法）。本项目只用 `.mjs`，不受此限。
8. **`c-run`/`c-io` 程序禁止中文输出**（控制台编码会让逐字比对失败）。

```powershell
"残留反引号: " + ([regex]::Matches($t,'`')).Count                         # 必须为 0
```
